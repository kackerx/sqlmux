## F4.1 快速 SQL 接上 M3 · 状态：passed（6b422b4；e2e ca50fc1）

- **依赖**：F3.5、F3.8
- **涉及**：`internal/app`（quick、palette、结果区）、`internal/keymap/default.toml`

**开发**
- [x] 读写判定换掉 `SelectLike`（M1 F1.7 用 `ponytail:` 标着）：`sqlkit.IsRead` 为假就不执行，结果区显示 `warn` 色的「写语句不在这里执行 · C-e 在 console 中打开」，键位文字从 keymap 读（§12「写语句」）。
- [x] 限行：判为读、且首词是 select / with / table / values 的仍走游标 + `FETCH FORWARD 101`，不改用自动 LIMIT（§12「不让服务端算完整个结果集」）。
- [x] `C-t`（SQL 范围、已有结果时）：结果作为固定 tab `quick #n` 进结果区，日志记一行，`R` 在 `Meta` 的只读事务里重跑，导出名 `quick-42.csv`，面板不关（§12「C-t 送到结果区」）。
- [x] `C-e`（Action `quicksql.edit`，`[keys.palette]` 里已经绑了）：在目标 pane 按 `console.new` 的规则开 console，已有内容时追加到末尾、前面空一行，光标落在 SQL 第一行，关面板、聚焦 console（§12「C-e 在 console 中打开」）。
- [x] 细节（worker 提议，已定）：
  - 只拦首词是 SQL 关键字、且 `IsRead` 为假的；首词不是关键字的（`selec 1` 这类拼错的）照旧发给数据库，报语法错误（f1.7）。关键字表补上 PG 全部语句的首词（按 PG 文档「SQL Commands」一节：copy、vacuum、refresh、reindex、cluster、comment、reset、discard、prepare、deallocate、move、close、notify、listen、unlisten、checkpoint、load、reassign、security、import、start、abort 等），console 里它们也顺带上色；加一个单测，把 PG 全部语句首词列一遍，逐个断言 `IsRead` 为假的都判为写。
  - 写语句的提示画在结果区第一行（报错的位置），标题行只剩「只读」；判为写的也记进历史，之后能找回再 `C-e`。
  - 删掉 `SelectLike`：「首词是 select / values / table / with」和 `AutoLimit` 里的判断是同一件事，快速 SQL 走不走游标和自动 LIMIT 共用这一处（reviewer 发现重复）。
  - `C-t` 在 SQL 范围由 `palette.open.tab` 分支处理，不另加 action；只在有结果集时起作用，报错、写语句提示、只有命令标签时不做事；送的是面板里已有的结果，不重跑；`quick #n` 的 n 和 `console_1 #42` 用同一个 `Session.RunSeq`；日志写 `quick  <首行>  N 行`（截断时 `N+`）；结果区被 `SPC r` 隐藏着也放进去并显示，焦点留在面板；同一个结果按两次就是两个 tab。`R` 重跑走快速 SQL 的执行（`Meta` 只读事务、游标 FETCH 101、search_path 取按 `R` 时树的 schema）。
  - 面板结果区标题右侧加 `C-y CSV  C-t 结果区  C-e console`，键位从 keymap 读，都能点击（F-04）；放不下时整项不显示，依次去掉 `C-e`、`C-t`、`C-y`，同查询条的让位。
  - 补全列表开着时 `C-e` / `C-t` / `C-y` 照常生效（`↵` / `esc` 仍归列表）；`C-y` 从 M1 起就有这个问题，一起改。
  - `R` 在固定的 `quick #n` 上原地替换，`#n` 和导出名不变（§12）。
  - `C-e` 取输入框里去掉 `;` 前缀后的文字（不是上次执行的），空的不做事；末尾不是空行先补一个；追加是一个撤销步；光标在 NORMAL、SQL 第一行行首；目标 pane 用 openTarget。

## F4.2 DDL 预览 · 状态：passed（6b422b4；e2e ca50fc1）

- **依赖**：F4.1
- **涉及**：`internal/app`（palette）、`internal/ui`（预览区）、`internal/db/postgres`（DDL）

**开发**
- [x] 选中项在表或视图上停留 150ms 后从 `Meta` 取 DDL，按表缓存；`R`（`tree.refresh`）时和列缓存一起清掉。每次移动选中项就重新计时，只取停下来的那一项；取回时选中项已经变了，只放进缓存、不显示。
- [x] PG 的 DDL 自己拼，先看 pgtui 的 `internal/db/metadata/`，提交说明里写明：
  - 表：`create table s.t (` 列（`format_type`、not null、default），约束用 `pg_get_constraintdef`，`);`，每个索引一行 `pg_get_indexdef`（主键和唯一约束已经带出来的索引跳过）；
  - 视图、物化视图：`pg_get_viewdef`。
  - MySQL 的 `SHOW CREATE TABLE` 在 M5。
- [x] 画法：列表下方的预览区，用 console 的配色高亮；出错时显示 `error` 色的原文。高度取剩余空间、最多 12 行；窗口不够高时先压缩预览区，列表至少留 3 行，底栏始终显示（§12「预览」）。
- [x] 细节（worker 提议，已定）：
  - 只在「所有」和表范围、选中项是表 / 视图时有预览；缓存键同列缓存，清列缓存时一起清；150ms 用 `tea.Tick` 加序号（同 which-key），鼠标悬停换了选中项也算移动。
  - 取回之前不占预览区，取回后才出现，免得列表高度跳两次；列表和预览怎么分高度见 §12「预览」（审查时改过）；超过 12 行截断，最后一行画 `dim` 色的 `…`，不滚动（`ponytail:`）。着色同 console，表名、列名也上色（F3.27）。
  - 取 DDL 加 3 秒超时，同计数（§8.3）：表被别的会话锁着时（PG 16 起 `pg_get_expr` 要拿表锁）不会一直占着 `Meta`。超时、取消这类 context 错误不缓存，下次停下来重取；数据库报的错（如表不存在）照旧缓存到 `R`。`TableColumns` 也会卡，是以前就有的，这次不动。
  - DDL：列写 `  name type [not null] [default …]`，约束写 `  constraint <name> <pg_get_constraintdef>`，都在括号里、逗号分隔；索引一行一个 `pg_get_indexdef;`，跳过 `pg_constraint.conindid` 指向的；视图 `create view s.v as` 加 `pg_get_viewdef(oid, true)`，物化视图 `create materialized view …` 并列出它的索引。identity 列写 `generated by default as identity` / `generated always as identity`（F3.32 起 catalog 里存的就是这个），不要写成 `default generated …`；generated 列、分区、继承、注释、owner、grant 不出，用 `ponytail:` 标出。

## F4.3 窗口·Pane 范围列出 tab 并显示层级 · 状态：passed（6b422b4；e2e ca50fc1）

用户 2026-09-30 提出：用面板找打开着的表或 console 时，要能看出它在哪个 session 的哪个 window、哪个 pane、哪个 tab，和树里的工作区一样。

- **依赖**：F0.14、F3.19
- **涉及**：`internal/app`（palette 的窗口·Pane 范围）

**开发**
- [x] `%` 范围除了 window、pane，每个打开着的 tab 也是一项（表、console、结果 tab），图标照 tab 的类型，名称是 tab 名，所在位置是完整的层级 `play › 0: data › pane-1`，和工作区节点的叫法一致（`pane-<n>`）；`↵` 切到这个 tab 并聚焦它的 pane（§12）。
- [x] pane 项的所在位置也改成 `play › 0: data`，window 项是 `play`；类型标签「Tab」。「所有」范围也列 tab（所有 = 除 SQL 历史外的全部种类）。M5 之前别的 window 的 tab 上 `↵` 不做事，同 window 项。
- [x] 细节（worker 提议，已定）：输入为空时排在最近用过的之后，照树的工作区顺序：window → 它的 pane（按 ⟨n⟩），每个 pane 后面紧跟它的 tab，然后是表、命令。列所有 window 的 tab，pane 项照旧只列当前 window 的；在别的 window 的 tab 上 `↵` 先切 window、再选中 tab、聚焦 pane，这一半留给 M5（多 window）。结果区的 tab、引导 tab 也列，和树一致（引导 tab 名「新 tab」，图标留空）。tab 项不记进「最近用过」：pane id 和 tab 位置每次启动都变，存不住，用 `ponytail:` 标出。
