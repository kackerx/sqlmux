## F6.5 布局文件 · 状态：draft

用户在 M2 / M3 验收期间提出（2026-09-30）。类似的做法：tmux-resurrect / tmux-continuum（退出前保存、启动时恢复）、tmuxinator / tmuxp 和 zellij 的布局文件（`zellij --layout`）、vim 的 `:mksession`，以及 DataGrip 重开时恢复上次的 console 和 tab。§5 的数据模型当初就设计成可序列化，这里补上读写。

- **依赖**：M5（一个 session 多个连接、多 window；布局里的大部分内容 M5 才有）、F6.3
- **涉及**：`internal/app`（工作现场的序列化与恢复）、`internal/config`（布局文件的读写与路径）、`cmd/sqlmux`（`--layout`）

**内容**（细节开工时由 worker 提议，决策者写进 §14）
- 记录什么：各 session 用到的连接；window 的名字、布局树和分割比例、缩放；每个 pane 的 tab 和当前 tab；表 tab 的连接、schema、表和 WHERE / ORDER / LIMIT / PAGE / COLS / 转置；console tab 的文件和 schema（SQL 本来就存在 console 文件里）；焦点、侧栏宽度、结果区高度。不记：未保存的单元格修改（退出前本来就要确认）、结果集、正在跑的查询。
- 格式用 TOML，和 config.toml 一样能手写、能分享；程序只改写它自己保存的那个文件。
- 退出时自动保存为 `last`，放在 `~/.local/state/sqlmux/last.toml`（程序写）；不管这次是怎么启动的，退出都覆盖它，同 DataGrip 重开总是上一次的样子。想留住的布局要另存成命名布局。
- 多个命名布局放在 `~/.config/sqlmux/layouts/<名字>.toml`（用户手写、分享；「保存布局为…」也写到这里，同名覆盖时手写的注释会丢）。命令面板里「保存布局为…」「打开布局」。
- 启动（2026-09-30 用户定）：
  - `sqlmux`（什么都不给）：恢复 `last`；没有 `last` 时照默认布局；
  - `sqlmux <连接名>`：用这个连接开默认布局，不恢复 `last`；
  - `sqlmux --layout <名字或路径>`：打开这个布局；
  - 连接名和 `--layout` 同时给时报错退出（「连接名和 --layout 只能给一个」），不悄悄忽略其中一个。
- 恢复时遇到的问题（连接不存在、表被删了、console 文件没了）只跳过那一项并 toast 提示，不影响其他部分，也不退出。

**验收**
- [ ] 退出再打开，window、pane、tab、各 tab 的查询条件和 console 都和退出前一样。
- [ ] 保存两个命名布局，`--layout` 分别打开，各自正确。
- [ ] 布局里的表被删掉后打开，其余部分正常恢复，给出提示。
