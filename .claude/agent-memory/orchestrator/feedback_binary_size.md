评估新引擎、新依赖时，二进制大小和 `CGO_ENABLED=0` 是用户会追问的成本。DuckDB 官方驱动让二进制 37 → 110 MB 时，用户的第一反应是「要评估下是否值得做…还不如做 mongodb」；找到 purego 运行时加载 libduckdb（+0.25 MB）后才拍板。

**Why:** 用户 2026-11-24 原话：「居然没有原生支持吗, 二进制要直接拉高这么多? 那就要评估下是否值得做了」。
**How to apply:** 给用户的方案对比里把二进制增量和是否要 cgo 单列一栏；有明显增量时先实测不涨的替代路（运行时加载、外部进程、纯 Go），再交给用户定。
